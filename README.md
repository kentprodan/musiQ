# musiQ

A local-library manager (tags, batch editing, folder scanning — MusicBee/
Mp3Tag/iTunes territory) fused with a self-hosted streaming client (Plex,
Subsonic/Navidrome — Plexamp territory), built as one Rust core with a
genuinely native UI shell on every platform.

See [`docs/architecture.md`](docs/architecture.md) for the full rationale
and target monorepo layout.

## Status: Phase 1

Only two things are real right now:

- **`core/musiq-core`** — a minimal Rust library: open/create a SQLite
  library database, recursively scan a folder for audio files, read their
  tags (`lofty`), and list tracks back out. Exposed to native clients via
  **`ffi/musiq-uniffi`**, a UniFFI adapter crate (C# bindings generated by
  [`uniffi-bindgen-cs`](https://github.com/NordSecurity/uniffi-bindgen-cs)).
- **`clients/windows-winui`** — a native WinUI 3 (Fluent 2) desktop shell:
  Mica backdrop, custom title bar, left `NavigationView`, and four real
  pages (Library, Now Playing, Sources, Settings) wired to the Rust core
  through the generated C# bindings.

Every other platform folder under `clients/` is a placeholder README
describing what will eventually live there — see
[`docs/architecture.md`](docs/architecture.md) for the plan.

## Building the Windows client

Prerequisites: .NET 10 SDK, the WinUI 3 `dotnet new` templates, Rust, and
`uniffi-bindgen-cs` (see `scripts/gen-bindings-cs.ps1` for the exact
install command). Then:

```powershell
cd clients/windows-winui/MusiqWindows
dotnet run
```

The project's `BeforeBuild` MSBuild target regenerates the C# bindings and
copies the native `musiq_uniffi.dll` automatically on every build.
